# État réel et conditions avant publication

Livré : noyau CLI/API et JSON-RPC stdio, workers sélectionnables, configuration par site, navigateur réel, journal durable, oracles explicites, deux sites synthétiques, tests de crash/reprise/budgets et benchmark contre Playwright écrit. Une intégration Codex réelle a produit deux décisions avant arrêt au budget ; l'intégration Antigravity est bloquée sur le poste testé. Aucun SaaS déployé, aucune campagne sur un site client réel.

| Priorité | Limite restante | Condition de levée |
|---|---|---|
| Bloquant web public | Pas d'isolation hostile intertenant, contrôle SSRF/DNS/metadata ou sandbox d'egress vérifiée. Route Playwright locale insuffisante. | Tests proxy/sandbox incluant DNS rebinding, WebRTC, popups et secrets de service ; revue indépendante. |
| Bloquant produit autonome | Deux décisions Codex ne constituent pas une évaluation d'autonomie ; faux positifs/recall, résistance cognitive à prompt injection et coût réel inconnus. | Plusieurs fournisseurs explicitement choisis, plafonds autorisés, mêmes scénarios randomisés/aveugles, revue et mesures de qualité/coût. |
| Bloquant hébergement | Store local seul, pas de queue/fencing/transactions multiutilisateurs, UI ou auth de service. | Développer architecture web, jobs sans retry implicite et tests d'isolation/arrêt d'ancien worker. |
| Bloquant données publiques | Masquage secrets connus et sélecteurs, mais PII inconnue/texte métier/canvas/images non garantis anonymes. | Classification, filtrage avant modèle, revue exports, coffre/rétention et audit de fuite ; aucune publication automatique des captures. |
| P1 intégration | Antigravity annonce 60 outils malgré le profil vide ; hook non attesté : refus. Gemini CLI nécessite un lecteur de quota réel. Codex natif essayé, sans facture financière mesurée. | Adapter un CLI à périmètre d'outils prouvé, conserver le refus initial ; tester les autres adaptateurs et réserver les API facturées via gateway conforme. |
| P1 sites divers | Origine unique et chemins exacts sans queries, POST de lecture ni WebSockets. Iframes, virtualisation, apps mobiles natives, SSO/MFA non implémentés. | Adaptateurs déclarés et tests synthétiques correspondants ; conserver refus par défaut. |
| P1 oracles | Prérequis propriétaire pour API de lecture indépendante, unités/date/fuseau/référence. UI seule et HTTP 200 non suffisants. | Documenter contrats d'oracle de chaque site ; sans eux livrer observations UI/hypothèses, pas verdict métier. |
| P1 reprise | Crash pendant préparation locale bloque ; job longue durée sans reconstruction automatique. Fin de ligne corrompue bloque, aucune réparation automatique. | Procédure de revue/migration signée, tests crash à plusieurs points (actuellement après mutation testé réellement). |
| P2 visualisation | Captures et overflow seulement ; pas de vision LLM, baselines pixel approuvées, a11y complète ou audit esthétique. | Tests visuels structurés et revue indépendante sans confondre différences de rendu et bugs. |
| P2 mesure | Deux sites simples, huit cas comparés une fois ; défauts semés connus. Pas de preuve statistique de généralisation. | Apps SSR/SPA distinctes, parcours inconnus, latence variable, répétitions à seeds publiées ; agents concurrents sur mêmes tâches. |
| P2 distribution | Dépôt source public MIT autorisé ; `private:true` bloque uniquement npm. Pas de service web public. Sources, tests, lockfile et copie indépendante vérifiés. | Garder artifacts/credentials hors Git ; nouvelle validation du propriétaire avant hébergement multiutilisateur. |

Les refus pré-requête sans oracle de refus restent intention incertaine avec preuve UI ; aucun rejeu. Une sauvegarde arrivant au-delà de la borne de collecte peut être interrompue par la politique : la réconciliation reste nécessaire. Il faut configurer les endpoints et délais du protocole sans les deviner.

Recommandation : poursuivre avec ce moteur comme couche de sécurité/preuve, tout en utilisant Playwright écrit pour les régressions stables. Essayer Stagehand/Browser Use comme adaptateurs de propositions de navigation ; ne leur déléguer ni consentement ni certification de sauvegarde. Choisir une solution SaaS existante si une plateforme collaborative complète est prioritaire sur le contrôle explicite des effets de bord. Ce noyau ne prétend pas les remplacer aujourd'hui.
